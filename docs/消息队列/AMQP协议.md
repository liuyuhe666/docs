# AMQP 协议

AMQP（**Advanced Message Queuing Protocol，高级消息队列协议**）是一种**面向消息中间件的开放标准协议**，用于在不同系统之间安全、可靠、高效地传输消息。

它最初由金融行业提出，用来解决**跨平台、跨语言的消息通信**问题。现在被广泛用于 **RabbitMQ、ActiveMQ、Qpid** 等消息队列系统中。

## 🧩 AMQP 的核心目标

AMQP 的设计目标主要包括：

1. **平台无关性**：不同语言、不同系统都可以通过 AMQP 通信。
2. **可靠性**：保证消息不丢失（支持持久化、确认机制）。
3. **灵活的消息路由机制**：通过 Exchange + Binding 实现灵活分发。
4. **安全性**：支持认证、加密（如 TLS）。
5. **事务与确认机制**：确保消息传输的一致性。

## 🧠 AMQP 模型结构

AMQP 协议定义了一个典型的消息路由模型，核心组件如下：

```
Producer ---> Exchange ---> Queue ---> Consumer
```

### 1️⃣ Producer（生产者）

负责发送消息到 **Exchange（交换机）**。
它只关心要发什么消息，不关心消息最终发给谁。

### 2️⃣ Exchange（交换机）

接收生产者发来的消息，并根据路由规则将消息分发到一个或多个 **Queue（队列）**。

Exchange 有几种类型（对应不同路由逻辑）：

| 类型        | 行为                             |
| ----------- | -------------------------------- |
| **Direct**  | 按照 routing key 精确匹配分发    |
| **Fanout**  | 广播给所有绑定的队列             |
| **Topic**   | 按模式匹配（支持通配符）分发消息 |
| **Headers** | 根据消息头部属性匹配路由         |

### 3️⃣ Queue（队列）

用于**存储消息**，直到消费者取走。
AMQP 保证每条消息只会被一个消费者消费（除非是广播模式）。

### 4️⃣ Binding（绑定）

是连接 **Exchange 和 Queue** 的规则。
它定义了 Exchange 怎样把消息路由到某个 Queue。

### 5️⃣ Consumer（消费者）

从队列中取出消息进行处理。
可以设置**自动确认**或**手动确认**消息是否已成功处理。

## ⚙️ AMQP 的可靠性机制

AMQP 内建多层可靠性保证：

| 机制                               | 说明                                 |
| ---------------------------------- | ------------------------------------ |
| **消息确认（ACK）**                | 消费者处理完后返回确认，防止消息丢失 |
| **持久化（Durable）**              | 队列和消息可持久化到磁盘             |
| **发布确认（Publisher Confirms）** | 确保生产者知道消息是否成功到达服务器 |
| **事务（Transaction）**            | 支持事务性发布与确认（性能较低）     |
| **死信队列（DLX）**                | 处理失败或过期消息的机制             |

## 🔐 AMQP 协议层结构（协议栈）

AMQP 定义了三个主要层级：

| 层级               | 作用                                                |
| ------------------ | --------------------------------------------------- |
| **Transport 层**   | 负责网络连接、认证、安全（类似 TCP）                |
| **Messaging 层**   | 定义消息的格式与交互（如 Exchange、Queue、Binding） |
| **Application 层** | 应用逻辑，如发布、订阅、消费消息                    |

## 🚀 AMQP vs 其他消息协议

| 特性     | **AMQP**                     | **MQTT**        | **Kafka**          |
| -------- | ---------------------------- | --------------- | ------------------ |
| 模型     | 队列模型（Exchange + Queue） | 发布/订阅模型   | 分区日志模型       |
| 可靠性   | 高（支持事务、ACK）          | 可调            | 高吞吐但非强事务   |
| 应用场景 | 企业消息系统、任务队列       | IoT、低带宽设备 | 大数据流处理       |
| 标准化   | ✅ 有标准（0-9-1 / 1.0）     | ✅              | ❌（Kafka 自定义） |

## 🧾 常见版本

- **AMQP 0-9-1**：RabbitMQ 采用的版本（最流行）
- **AMQP 1.0**：由 OASIS 标准化，支持更多消息中间件间互操作（如 Azure Service Bus）

## 🧰 典型使用流程（以 RabbitMQ 为例）

```text
1. Producer 连接到 Broker
2. Producer 声明 Exchange，并发送消息
3. Exchange 根据 Binding 路由消息到 Queue
4. Consumer 从 Queue 中接收消息
5. Consumer 处理后发送 ACK
```

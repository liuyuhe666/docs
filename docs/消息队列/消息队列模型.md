# 消息队列模型

消息队列（Message Queue, MQ）的**模型**主要指消息在系统中流动、存储、传递和消费的方式。

不同的模型适用于不同的业务场景。总体上可以分为以下几类主流模型 👇

## 🧩 点对点模型（Point-to-Point, P2P）

**核心概念：** 队列（Queue）

### 工作机制

- 生产者（Producer）将消息发送到一个特定的**队列**；
- 消费者（Consumer）从队列中接收消息；
- 每条消息**只会被一个消费者接收一次**；
- 消费后消息会被移除。

### 特点

- **一对一通信**；
- **可靠传递**（通常配合确认机制）；
- 消息消费后不再保留。

### 应用场景

- 任务分发：例如订单系统将任务分发给多个工作进程；
- 异步处理：如邮件发送、图像处理、日志收集。

### 示例

| 实现     | 示例                 |
| -------- | -------------------- |
| ActiveMQ | Queue 模式           |
| RabbitMQ | Work Queue           |
| IBM MQ   | 基于队列的点对点传输 |

## 🧠 发布-订阅模型（Publish-Subscribe, Pub/Sub）

**核心概念：** 主题（Topic）

### 工作机制

- 生产者（发布者）向一个主题发布消息；
- 多个消费者（订阅者）可以订阅该主题；
- 每个订阅者都会**接收到同一条消息的副本**。

### 特点

- **一对多通信**；
- 解耦发布者和订阅者；
- 可支持**广播**或**多组订阅消费**。

### 应用场景

- 实时消息广播（如系统通知、价格变动推送）；
- 事件驱动系统；
- 微服务间的事件流。

### 示例

| 实现          | 示例                           |
| ------------- | ------------------------------ |
| Kafka         | Topic + Consumer Group         |
| Redis Pub/Sub | 主题广播                       |
| RabbitMQ      | Exchange（fanout、topic 模式） |

## 🔄 流式消息模型（Streaming Model）

**核心概念：** 日志（Log）或流（Stream）

### 工作机制

- 消息被**顺序追加**到一个不可变的日志中；
- 消费者维护自己的**偏移量（offset）**；
- 可以**重复读取**历史消息（回溯、重放）。

### 特点

- 保留所有消息（可配置保留时间）；
- 支持**多消费者独立消费**；
- 适合大规模流数据处理。

### 应用场景

- 日志收集与分析（ELK/Kafka）；
- 实时流计算（Flink / Spark Streaming）；
- 数据管道与事件溯源。

### 示例

| 实现         | 示例               |
| ------------ | ------------------ |
| Apache Kafka | 分区日志流模型     |
| Pulsar       | 分区 + 多租户流    |
| Redpanda     | Kafka 兼容流式模型 |

## 🧱 四、混合模型（Hybrid）

某些消息中间件支持多种模型组合：

### 例子

- **RabbitMQ**
  同时支持队列（P2P）与交换机（Pub/Sub）模式；
- **RocketMQ / Pulsar**
  支持既像 Kafka 那样的流式模型，又支持可靠队列语义；
- **Azure Service Bus / AWS SQS + SNS**
  可组合为点对点 + 发布订阅混合架构。

## 🧭 模型对比

| 特征           | 点对点 (Queue)      | 发布订阅 (Topic)        | 流式消息 (Log/Stream)     |
| -------------- | ------------------- | ----------------------- | ------------------------- |
| 消费模式       | 单消费者            | 多消费者                | 多消费者（独立 offset）   |
| 消息是否持久   | 可配置              | 可配置                  | 默认持久                  |
| 消息是否可重放 | 否                  | 否                      | 是                        |
| 顺序保证       | 队列级              | 不保证                  | 分区级顺序                |
| 典型系统       | RabbitMQ / ActiveMQ | Redis / RabbitMQ / MQTT | Kafka / Pulsar / Redpanda |
